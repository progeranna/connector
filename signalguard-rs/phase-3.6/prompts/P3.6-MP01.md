## 1. Authority and purpose

This contract records a direct product-owner correction to the SignalGuard RS frontend interaction model.

It is authoritative over every older planning, architecture, smoke-matrix, route-inventory, checkpoint, or implementation clause that requires any of the following:

- a standalone visual symbol-detail page at `/symbols/:symbol`;
- a standalone visual anomalies page or anomaly explorer at `/anomalies`;
- route-versus-popup presentation parity;
- route-to-route symbol-detail continuity;
- preservation of placeholder symbol/anomaly page routes as user-facing pages;
- Phase 4 implementation of a standalone anomaly explorer page.

Those older clauses are superseded only for frontend navigation and visual-surface semantics. Data isolation, canonical symbol identity, Demo/Live separation, read-only behavior, query ownership, accessibility, bundle policy, backend APIs, and the closed Phase 3.5 evidence remain authoritative.

Phase 3.5 remains closed and immutable at its published checkpoint. This is a narrow post-checkpoint corrective phase. Phase 4 remains unauthorized until this correction is independently reviewed and integrated.

## 3. Binding product UX invariants

The final implementation must satisfy all of the following:

1. Clicking a market or symbol row/card opens `Symbol Detail` as a modal overlay above Dashboard.
2. Clicking an anomaly row/card opens `Anomaly Detail` as an overlay dialog above Dashboard. It must not open Symbol Detail automatically.
3. `View all anomalies` opens the existing `All Anomalies` modal. It must not navigate to a page.
4. There is no standalone visual screen for `/symbols/BTCUSDT`, `/symbols/ETHUSDT`, or any other `/symbols/:symbol` path.
5. There is no standalone visual screen for `/anomalies`.
6. The only user-facing console pages are `/` and `/dashboard`; both render Dashboard.
7. Legacy frontend paths `/symbols/:symbol` and `/anomalies` may remain only as explicit compatibility redirects to `/dashboard`. They must not render standalone page content and must not create a second visual navigation mode.
8. URL-synchronized modal deep links are not authorized by this correction. Do not auto-open a modal from a legacy route or introduce new modal URL state.
9. The backend HTTP endpoint `/anomalies` remains unchanged. Removing the frontend page route must not remove or rename the API endpoint.
10. The header symbol selector updates the selected Dashboard symbol only. It never navigates to `/symbols/:symbol`.

## 4. Required behavior

### 4.1 Symbol interaction

- Market Health preview rows/cards open the existing Symbol Detail modal.
- All Market Health rows/cards open the existing Symbol Detail modal.
- Symbol Detail remains keyed by exact `{ mode, symbol, returnContext }` identity.
- Demo/Live and BTC/ETH isolation, loading/error/unavailable states, retry behavior, source labels, focus behavior, and no-fallback rules remain unchanged.
- Closing Symbol Detail returns to the exact triggering control.
- Existing Back behavior from Symbol Detail to All Markets remains available when opened from All Markets.

### 4.2 Anomaly interaction

- Recent Anomalies desktop rows and mobile cards must accept an exact anomaly activation callback, not a symbol-only callback.
- The callback identity is the accepted anomaly UUID. Do not use array index, symbol, message, timestamp, or object position as identity.
- Clicking or keyboard-activating an anomaly opens Anomaly Detail for that exact anomaly.
- Anomaly Detail must display only fields present in the accepted `DashboardAnomaly` model:
  - symbol;
  - detector/anomaly type;
  - severity;
  - message/context;
  - observed value;
  - threshold value;
  - event time;
  - created time;
  - anomaly UUID.
- Preserve numeric zero. Render null numeric values with the existing unavailable/em-dash convention. Do not fabricate evidence, status, explanation, trading meaning, or detector fields.
- Reuse existing accepted anomaly formatting and severity presentation functions where applicable.
- Anomaly Detail must be an accessible overlay dialog. Use the existing Dashboard modal/dialog boundary rather than introducing a new dependency or a second dialog framework.
- If the current modal primitive cannot visually implement a drawer without new infrastructure, use a normal modal. A standalone page is forbidden.
- Opening an anomaly from All Anomalies must preserve return context. A Back action must return to All Anomalies; Close must close the overlay stack and return focus appropriately.
- On Demo/Live mode change, stale anomaly content from the previous mode must not remain visible under the new mode. Resolve by UUID against the active summary; when no matching active anomaly exists, close Anomaly Detail or return to All Anomalies according to its return context.

### 4.3 All Anomalies

- `View all anomalies` continues to open `AllAnomaliesModal` over Dashboard.
- Rows/cards inside All Anomalies open Anomaly Detail, not Symbol Detail.
- All Anomalies remains bounded to the current Dashboard summary in this correction. Do not add server pagination, filters, exports, mutation, acknowledgement, or a standalone explorer.

### 4.4 Legacy routes

- `/` renders Dashboard.
- `/dashboard` renders Dashboard.
- `/symbols/:symbol` redirects with replacement semantics to `/dashboard`.
- `/anomalies` redirects with replacement semantics to `/dashboard`.
- Legacy routes must not render Symbol Detail, Anomaly Detail, All Anomalies, placeholder copy, sample links, or page-specific shells before or after redirect.
- Unknown-route behavior is outside this contract unless a minimal change is strictly required by the router implementation.
