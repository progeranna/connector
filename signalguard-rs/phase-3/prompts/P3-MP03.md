## Goal

Create one pure TypeScript semantic model that later UI microphases can consume without duplicating strings, classification rules, tooltip fact structures, or time labels.

The module must contain no JSX, React hook, DOM access, network access, cache/store access, side effect, or presentation wiring.

## Binding visible vocabulary

### System

Exact labels:

- `System Healthy`;
- `System Degraded`;
- `System Critical`;
- `System Offline`;
- `System Unknown`.

Use a typed system status key vocabulary equivalent to:

- `healthy`;
- `degraded`;
- `critical`;
- `offline`;
- `unknown`.

### Market

Exact labels:

- `Market Healthy`;
- `Market Degraded`;
- `Market Critical`;
- `Market Stale`;
- `Market No Data`.

Use a typed market status key vocabulary equivalent to:

- `healthy`;
- `degraded`;
- `critical`;
- `stale`;
- `no_data`.

Do not collapse stale data into unavailable or health degradation. Availability, freshness, and health remain distinct input concepts.

### Anomaly

Severity vocabulary:

- `info`;
- `warning`;
- `critical`.

Detector display must support current detector identifiers:

- `price_move` → `Price Move`;
- `spread_spike` → `Spread Spike`;
- `stale_data` → `Stale Data`;
- `trade_burst` → `Trade Burst`;
- `quote_stuck` → `Quote Stuck`;
- `event_lag_spike` → `Event Lag Spike`;
- `depth_sequence_gap` → `Depth Sequence Gap`.

Combined active labels must use the exact format:

`<Severity label> · <Detector label>`

Examples:

- `Warning · Spread Spike`;
- `Critical · Price Move`;
- `Info · Stale Data`.

The no-active state label is exactly:

`No Active Anomalies`

Unknown detector identifiers must be formatted deterministically from snake_case without throwing or silently mapping to another detector.

### Data age

Exact labels:

- `Fresh`;
- `Delayed`;
- `Stale`;
- `No Data`.

Create a pure classifier that accepts explicit inputs rather than reading global configuration:

- `ageMs: number | null`;
- `delayedAfterMs: number`;
- `staleAfterMs: number`.

Required classification:

- `ageMs === null` → `no_data`;
- `ageMs < delayedAfterMs` → `fresh`;
- `delayedAfterMs <= ageMs < staleAfterMs` → `delayed`;
- `ageMs >= staleAfterMs` → `stale`.

Boundary values are inclusive as written.

Invalid inputs must be handled deterministically. Prefer explicit validation/error for negative ages, non-finite values, negative thresholds, or `delayedAfterMs > staleAfterMs`; do not silently invent a corrected threshold.

## Descriptor contract

Define a small reusable descriptor shape containing at least:

- stable semantic key;
- exact visible label;
- `StatusTone` compatible tone;
- one short explanatory sentence suitable for a tooltip body.

The module may import the `StatusTone` type from `web/src/shared/lib/status.ts`, but must not modify the tone palette.

Do not embed Tailwind classes, React nodes, icons, colors, or component names in semantic descriptors.

## Tooltip facts and time semantics

Define pure typed structures for later tooltip composition:

### Tooltip fact

At minimum:

- `label: string`;
- `value: string`.

### Time fact labels

Exact allowed labels:

- `Last evaluated`;
- `Last event`;
- `Detected`.

Time facts must preserve a supplied display value and must not call `Date.now()` or format dates implicitly in this module.

Provide a narrow helper to create/filter tooltip facts only if it remains pure and deterministic. Empty/null optional facts may be omitted, but a numeric zero or non-empty string must not be lost through truthiness checks.

The target tooltip composition for later waves is:

- entity title;
- one short explanation;
- one to three facts;
- one appropriate time fact.

P3-MP03 defines the model only; it does not render this composition.

## Tone mapping requirements

- healthy/fresh → `healthy`;
- degraded/delayed/warning → `degraded` or `warning` as semantically appropriate;
- critical/stale/critical anomaly → `critical`;
- offline/no data/unknown/no active anomalies → `neutral` unless a more precise existing non-alarming tone is justified and tested;
- info anomaly → `info`.

Do not add new values to `StatusTone` and do not edit `shared/lib/status.ts`.
