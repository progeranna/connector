## Goal

Publish one reusable typed smoke-matrix definition that later Phase 3 tests and manual preview checklists can consume without re-inventing coverage dimensions.

The manifest must make the following coverage explicit:

### Public modes

- `demo`;
- `live`.

Do not add `replay` or any third public UI mode.

### Canonical markets

- `BTCUSDT`;
- `ETHUSDT`.

### Public surfaces

- dashboard;
- symbol detail route;
- symbol detail popup.

### Responsive targets

- desktop;
- mobile.

Use deterministic named viewport metadata rather than reading the real window during module initialization. Include explicit width values suitable for later preview/test use.

### Resource/presentation states

- loading;
- error;
- empty;
- unavailable/non-observed;
- observed success.

### Identity and interaction scenarios

- steady-state render;
- Demo → Live;
- Live → Demo;
- BTC → ETH;
- ETH → BTC;
- route → route;
- popup → popup;
- route/popup parity;
- late response after mode switch;
- late response after symbol switch;
- invalid or missing Live symbol without Demo fallback.

### Dialog scenarios reserved for later accessibility work

Represent, but do not implement UI behavior for:

- Escape close;
- backdrop close;
- focus containment;
- initial focus;
- focus return;
- body scroll lock.

The matrix must distinguish current smoke expectations from later Wave 5 dialog requirements. Do not claim unimplemented focus behavior currently passes.

## Design requirements

1. Add a pure TypeScript manifest with exported literal unions/types and readonly scenario collections.
2. Give every scenario a stable unique identifier.
3. Keep scenario ordering deterministic.
4. Do not depend on React, DOM globals, timers, network requests, localStorage, or TanStack Query.
5. Do not execute tests or side effects when the manifest is imported.
6. Avoid one enormous opaque Cartesian-product array when smaller named scenario groups make intent clearer.
7. Provide narrow helper functions only when they improve reuse, such as filtering by surface or listing required scenario IDs.
8. Preserve exact public terminology: Demo, Live, dashboard, symbol route, symbol popup.
9. No production code may import this test-only manifest.
10. Do not create screenshots or generated snapshots.

## Required executable tests

The tests must prove at least:

1. the mode vocabulary is exactly `demo|live`;
2. the canonical market vocabulary is exactly `BTCUSDT|ETHUSDT`;
3. the surface vocabulary contains dashboard, symbol route, and symbol popup;
4. desktop and mobile viewport targets have deterministic distinct widths;
5. loading, error, empty, unavailable, and success are all represented;
6. every required mode × symbol × surface identity has at least one success scenario;
7. every surface has desktop and mobile coverage;
8. every required switch/race/parity scenario is represented;
9. invalid/missing Live identity explicitly forbids Demo fallback;
10. dialog requirements are represented without falsely marking all future focus behaviors as already implemented;
11. scenario IDs are unique and collections are deterministically ordered;
12. no scenario contains a Replay public mode;
13. importing the manifest has no side effect and requires no DOM setup.

Tests must be deterministic and must not use sleeps or snapshots.
