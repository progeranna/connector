## Goal

Add an accessible, dependency-free, reusable tooltip foundation that later semantic microphases can adopt one caller at a time.

The primitive must:

- expose tooltip content through `role="tooltip"`;
- connect the trigger and tooltip using `aria-describedby` only while the tooltip is available to the user;
- open on pointer hover and keyboard focus;
- close on pointer leave and focus leaving the trigger/tooltip group;
- close on Escape while open;
- preserve the trigger's existing event handlers and accessible name;
- generate collision-free IDs when multiple tooltips render;
- require no global CSS and no third-party dependency;
- render no portal and perform no caller migration in this microphase;
- remain a tooltip, not a dialog, popover menu, or click-only disclosure.

## Narrow public API

Create a clear shared component API. A recommended shape is:

- one exported `Tooltip` component;
- `content: React.ReactNode`;
- exactly one trigger child or an equally narrow render-trigger contract;
- optional stable `id` for tests/controlled composition;
- optional placement vocabulary only if implemented entirely with local classes and covered by tests.

Do not add speculative configuration, animation systems, delay managers, providers, global registries, portals, floating-position libraries, or compound-component APIs.

If cloning a trigger element, compose rather than overwrite existing handlers and refs where practical. If a wrapper-based API is selected, the wrapper must not break keyboard focus or the trigger's semantic element.

## Interaction requirements

1. Closed by default.
2. Pointer entering trigger opens it.
3. Pointer leaving the combined trigger/tooltip interaction area closes it.
4. Trigger focus opens it.
5. Blur/focus leaving the combined interaction area closes it.
6. Escape closes it without activating the trigger.
7. Trigger click behavior is not consumed or changed.
8. Tooltip content itself is not a focus trap and must not introduce interactive controls in this primitive contract.
9. Multiple instances remain independent.
10. The component works under React Strict Mode.

No sleep-based delay is required. Prefer immediate deterministic behavior for this foundation.

## Presentation requirements

Do not change global colors, typography, dashboard layout, or any existing caller.

## Required executable tests

Tests must prove at least:

1. tooltip is absent/hidden from tooltip role before interaction;
2. hover opens it;
3. pointer leave closes it;
4. focus opens it;
5. blur/focus departure closes it;
6. Escape closes it;
7. trigger receives `aria-describedby` tied to the rendered tooltip;
8. existing trigger click and pointer/focus handlers still run;
9. accessible trigger name remains unchanged;
10. two instances receive independent IDs and state;
11. rerender does not create duplicate live tooltip IDs;
12. unmount cleans up without document-level listener leakage;
13. no portal/root/global provider is required.

Use Testing Library user events available through existing dependencies or direct fireEvent APIs already installed. Do not add a package solely for tests. Do not use snapshots or sleeps.
