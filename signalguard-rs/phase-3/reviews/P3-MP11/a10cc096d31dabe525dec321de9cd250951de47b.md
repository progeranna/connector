## Exact type-safety defect

The committed test includes a typed table with this case:

```ts
["custom", "Custom", ["border-white/10", "bg-white/5", "text-slate-200"]]
```

The callback passes that first element directly as:

```ts
previewRow("STATUSUSDT", { healthStatus })
```

```ts
z.enum(["healthy", "degraded", "unhealthy"])
```

Therefore `"custom"` is not assignable to the accepted health-status union. Runtime tests can pass because Vitest executes transpiled JavaScript, but repository TypeScript typecheck correctly rejects the fixture.

The exact Actions log response available to the orchestrator is truncated before diagnostic text, so this review does not quote an unavailable compiler line. The root cause is nevertheless deterministic from the committed typed source and accepted type definition.
