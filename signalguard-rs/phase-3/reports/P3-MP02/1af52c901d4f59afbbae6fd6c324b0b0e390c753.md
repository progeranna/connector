## Interaction and ARIA evidence

The implementation and focused tests establish the following behavior:

- Tooltip content is absent before interaction.
- Pointer entry opens it; pointer departure closes it when no focus source remains.
- Focus entering the wrapped trigger group opens it; focus departure closes it.
- Escape dismisses an open tooltip and does not activate the child trigger.
- The live content has `role="tooltip"` and an ID.
- The trigger receives the tooltip ID through `aria-describedby` only while the tooltip is available.
- A pre-existing `aria-describedby` value is preserved and combined with the live tooltip ID, then restored after close.
- React `useId` provides independent IDs across multiple instances and Strict Mode rerenders; an explicit `id` remains available for deterministic callers.
- Existing child click, focus, and pointer-enter handlers remain callable, and tooltip content does not replace the child accessible name.
- The Escape listener is installed only while open and is removed on close or unmount.
- The tooltip renders inline within its host subtree, proving there is no provider or portal dependency.
- The component does not migrate or alter any existing caller.
