## Metric behavior

For observed rows, the model exposes the exact supplied values:

- health score;
- health status;
- last trade price;
- spread percentage;
- trades per minute;
- last event age in milliseconds.

Numeric zero is preserved exactly for score, spread, trades per minute, and last-event age. Exact status and price strings are preserved. A metric becomes `null` only when that observed field is absent.

For configured, awaiting, and unavailable rows, all six metrics are forced to `null`, even when the input object improperly contains non-null state or health payloads.

## Limit and result metadata behavior

- Default limit: `7`.
- Custom finite non-negative integer limits are accepted.
- Limit `0` returns no visible rows while preserving `allRows`, total count, hidden count, and `hasMore`.
- Fewer-than-limit: all rows visible, hidden count `0`, `hasMore=false`.
- Equal-to-limit: all rows visible, hidden count `0`, `hasMore=false`.
- Greater-than-limit: visible rows are sliced to the limit, hidden count is the remainder, `hasMore=true`.
- Empty input returns `allRows=[]`, `rows=[]`, `totalCount=0`, `hiddenCount=0`, `hasMore=false`, `isEmpty=true`.
- Negative limits throw `RangeError: limit must be non-negative`.
- Fractional, `NaN`, and infinite limits throw `TypeError: limit must be a finite integer`.
