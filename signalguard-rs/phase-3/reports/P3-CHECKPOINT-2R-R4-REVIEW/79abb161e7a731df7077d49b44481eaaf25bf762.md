## Independent production-source review

### Removal of the causal suppression

At the immutable base, `DashboardTablesGrid` held `previousUiModeRef`, computed `modeChanged`, replaced popup mode first, and reconciled the symbol only under:

`!modeChanged && selectedSymbol && nextIdentity.symbol !== selectedSymbol`

The worker removes `previousUiModeRef`, `modeChanged`, and that `!modeChanged` suppression only from the modal identity replacement/reconciliation logic. No unrelated focus, routing, resource, presentation, or storage logic is changed.

### Single reconciliation path

The worker adds one narrow helper:

`reconcileSymbolPopupIdentity(identity, selectedUiMode, selectedSymbol)`

It:

1. replaces the identity mode only when needed;
2. if the already-resolved `selectedSymbol` is non-null and differs, replaces the symbol on that same derived identity;
3. returns the combined identity.

The helper receives the existing selected-symbol result passed from `DashboardPage`; it does not read or create independent storage.

### Immediate render and state replacement use the same semantics

For an open `symbolDetail`, `activePopupIdentity` now calls the same reconciliation helper used by the modal-state replacement effect. The resource/render identity therefore does not retain the old symbol when mode and selected symbol change together.

For nested `symbolAnomalyDetail`, the effect derives from `parentIdentity` using the same helper and, when the parent changes, collapses the state to `{ type: "symbolDetail", identity: nextIdentity }`. This clears the stale nested anomaly UUID while producing the combined new mode/new-symbol parent rather than accepting an intermediate `demo:ETHUSDT` owner.

### Return context preservation

The existing unchanged helper `replaceSymbolPopupSymbol` recreates identity with `identity.mode`, the replacement symbol, and `identity.returnContext`. `replaceSymbolPopupMode` spreads the existing identity and replaces only mode. Therefore the new combined reconciliation preserves `returnContext` through both replacements.

### Same-mode and mode-only behavior

The helper preserves both adjacent cases:

- same-mode symbol change: mode replacement is skipped, then the symbol is replaced;
- mode change with unchanged selected symbol: mode is replaced and no symbol replacement is needed.

The pre-existing tests for these dimensions remain present.
