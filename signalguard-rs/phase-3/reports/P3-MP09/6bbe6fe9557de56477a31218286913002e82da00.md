## Binding precedence

The resolver implements the contract precedence in this order:

1. Existing `DashboardSummary` data wins over all background query flags, including an edge-case `isLoading=true` input.
2. With no data, active `isLoading` or `isFetching` returns blocking `loading`, including when `isError=true` is also supplied.
3. With no data and no active loading/fetching, `isError=true` returns blocking `error` with the original error reference.
4. With no data and no loading/fetching/error condition, the resolver returns `empty` with `summary: null` and reason `no-data`.

A supplied summary is empty only when both `summary.symbols.length === 0` and `summary.recent_anomalies.length === 0`. Pipeline or service status does not redefine emptiness.

## Cached data and background errors

When data exists:

- cached successful data remains `success` while `isFetching=true` and exposes `isRefreshing=true`;
- cached empty data remains `empty` while `isFetching=true` and exposes `isRefreshing=true`;
- a background error does not erase cached successful or empty data;
- `refreshError` is the original supplied error by reference when `isError=true`, otherwise `null`;
- `isRefreshing` is exactly the supplied `isFetching` value.
