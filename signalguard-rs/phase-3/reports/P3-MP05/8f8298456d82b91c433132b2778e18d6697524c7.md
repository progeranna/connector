## Exported production API

### `NormalizedTimelinePoint`

Readonly normalized point type containing:

- `timestamp: string`
- `timestampMs: number`
- `price: number`
- `priceLabel: string`
- `spreadPct: number | null`
- `tradesPerMinute: number | null`
- `lastEventAgeMs: number | null`

### `normalizeTimelinePoint`

Signature:

`normalizeTimelinePoint(point: MarketTimelinePoint): NormalizedTimelinePoint | null`

Normalizes one accepted DTO and returns `null` only when the timestamp or price makes the point unusable.

### `normalizeTimelinePoints`

Signature:

`normalizeTimelinePoints(points: readonly MarketTimelinePoint[]): readonly NormalizedTimelinePoint[]`

Returns a new readonly-compatible array containing only valid normalized points in original input order.

## Binding normalization behavior

### Timestamp

- Uses `Date.parse(point.timestamp)` deterministically.
- Rejects the whole point when the parsed result is non-finite.
- Preserves the original timestamp string exactly in accepted output.
- Does not call current time and does not substitute a timestamp.

### Price

- Treats price as its source string.
- Rejects empty and whitespace-only price strings before numeric conversion.
- Converts the original string with `Number`.
- Rejects non-finite numeric results, including `NaN`, positive infinity, and negative infinity spellings.
- Preserves the original exact source string as `priceLabel` without formatting, rounding, or rewriting.
- Accepts finite zero.
- Accepts finite negative values at this normalization layer.
- Does not calculate price-domain policy.

### Optional numeric fields

Each optional field is normalized independently and never invalidates an otherwise usable point:

- `spread_pct` becomes `spreadPct`; every finite number is preserved, including zero and negatives, otherwise `null`.
- `trades_per_minute` becomes `tradesPerMinute`; every finite non-negative number is preserved, including zero, otherwise `null`.
- `last_event_age_ms` becomes `lastEventAgeMs`; every finite non-negative number is preserved, including zero, otherwise `null`.

### Invalid points

- Invalid timestamp: point rejected.
- Empty or whitespace-only price: point rejected.
- Nonnumeric or non-finite price: point rejected.
- Invalid optional field: field becomes `null`; point remains accepted when timestamp and price are valid.

### Order, duplicates, and immutability

- Preserves original valid-point input order exactly.
- Does not sort, deduplicate, merge, interpolate, or mutate.
- Preserves duplicate timestamps.
- Preserves duplicate prices.
- Returns a new array rather than the input array.
- Does not mutate input point objects.
- Equal inputs produce equal output values.
