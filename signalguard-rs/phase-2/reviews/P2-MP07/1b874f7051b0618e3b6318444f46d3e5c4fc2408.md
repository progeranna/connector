## Accepted implementation

### Backend and public contract

- public `source` is explicit and typed as `demo|live`;
- public `availability` is explicit and typed as `observed|configured|awaiting|unavailable`;
- Demo summary and symbols report `demo/observed`;
- Live dashboard catalog is the canonical union of configured and Redis-registered symbols;
- catalog identity is deduplicated and lexicographically ordered;
- availability is derived deterministically from observed state, configured membership, runtime mode, and runtime status;
- non-observed entries keep `state=null` and `health=null`;
- successful market state/health responses report `live/observed`;
- timeline source matches the requested public mode;
- symbols and anomalies responses report `live`;
- Live does not inject Demo-only symbols or values;
- the dashboard preserves exactly one bulk `get_market_states` read and introduces no awaited per-symbol cache GET loop.

### Frontend boundary and presentation

- Zod schemas require exact source and availability fields;
- requested source identity and parent/child source identity are validated before rendering;
- the frontend no longer joins `/runtime/mode` to manufacture Live catalog availability;
- the old `configured-unobserved` shadow vocabulary is removed;
- route and popup use the same explicit source/availability view-model boundary;
- non-observed symbols do not request dashboard timeline data;
- configured, awaiting, and unavailable symbols render exact explicit empty-state copy;
- non-observed symbols do not render price, spread, rates, freshness, health score, chart, anomaly count, or generic zero-anomaly copy;
- pipeline age is not substituted as selected-symbol freshness;
- absent source identity does not default to Demo;
- the global header remains neutral when there are no observed symbols, even if the pipeline is healthy;
- existing routes, popup workflow, navigation, selected identity, Demo/Live isolation, responsive surfaces, and observed-data presentation remain intact.
