## Semantic review

### Bulk cache API

The new API uses one Redis `MGET`, not a loop of awaited `GET` operations. The response pairs each requested `Symbol` explicitly with `Option<MarketState>` and preserves order and duplicates.

Empty input returns immediately. Missing first, middle, or last values remain `None` in their requested positions. Redis result-count mismatch is rejected. Malformed JSON identifies the requested symbol. Embedded-symbol mismatch identifies both requested and embedded symbols and fails as `CacheError::InvalidData`.

The in-memory implementation preserves the same pairing/order behavior and validates embedded identity.

### Dashboard path

The Live dashboard now retrieves all market states once and builds summaries without an awaited cache call inside the per-symbol transformation. State, health, anomaly filtering, missing-state `null` values, symbol ordering, Demo mode, public response shape, and cache-error mapping are preserved.

### P2-MP05 preservation

The atomic Lua script is byte-for-byte unchanged from the assigned base. It still validates both Redis key types before mutating either key, then performs `SET` and `SADD` atomically.
