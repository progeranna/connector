## Design review

The implementation replaces sequential `SET` and `SADD` calls with one Lua script invocation. The script:

1. validates that the state key is absent or a string;
2. validates that the symbol index is absent or a set;
3. returns a deterministic error before mutation when either type is incompatible;
4. performs `SET` and `SADD` only after both checks pass.

This matches the contract's required protection against the deterministic wrong-type partial-write cases. Serialization remains before Redis mutation, key names and JSON representation remain unchanged, and Redis errors remain mapped through the existing `set_market_state` operation context.

The added ignored tests cover successful/repeated writes, getter/list compatibility, unrelated-key preservation, wrong symbol-index type, and wrong state-key type. Their assertions inspect Redis contents after failure rather than checking only the returned error.
