## Correctness review

The implementation uses one Redis Lua script rather than plain `MULTI/EXEC` or two independent commands.

Before mutation, the script validates:

- state key: `none|string`;
- symbol-index key: `none|set`.

Only after both validations pass does it execute:

- `SET` on `signalguard:market_state:<SYMBOL>`;
- `SADD` on `signalguard:symbols`.

This satisfies the contract's deterministic both-or-neither requirement for command-level wrong-type failures. Payload serialization remains outside Redis mutation, so serialization errors cannot leave partial Redis state.
