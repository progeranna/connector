## Goal

Centralize frontend TanStack Query key construction so request identity is explicit, stable, serializable, and independently testable without changing endpoint behavior.

## Required implementation

Create a cohesive query-key module, preferably:

`web/src/features/dashboard/queryKeys.ts`

Migrate current query-key construction out of:

`web/src/features/dashboard/api.ts`

At minimum, preserve and centralize the exact-base key families for:

- dashboard summary;
- market timeline;
- runtime mode/status.

Inspect the exact base before editing. Move additional existing keys only when they are already used by current hooks and the move requires no endpoint, fetch, policy, or behavior change.

Preserve compatibility re-exports from `api.ts` when existing consumers or tests depend on them.

## Identity requirements

Executable tests must prove all of the following:

1. Demo summary and Live summary use distinct keys.
2. BTC timeline and ETH timeline use distinct keys.
3. Summary identity differs from timeline identity.
4. Runtime identity differs from market-resource identity.
5. Equal inputs produce structurally equal stable keys.
6. Symbol identity passes through the existing canonical `SymbolId` boundary.
7. Case and surrounding whitespace normalize consistently through that boundary.
8. Absent or invalid symbol input preserves the current disabled-query identity and never aliases a valid symbol.
9. Popup presentation state is not included in a server-resource key.
10. Mode-wide summary remains mode-wide when the endpoint itself is not symbol-owned.
11. Every parameter that determines returned server data appears in the key identity.

Use readonly serializable tuples or an equivalently stable structure.
