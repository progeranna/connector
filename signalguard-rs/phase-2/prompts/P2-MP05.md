## Goal

Make Redis latest-state payload storage and symbol-index registration behave as one atomic logical operation.

Current logical records:

- `signalguard:market_state:<SYMBOL>`
- `signalguard:symbols`

A successful write must make both records available together.

A rejected or deterministic failing write must leave neither newly created partial record.

## Critical Redis rule

Do not assume `MULTI`/`EXEC` rolls back earlier successful commands after a later command-level error.

A plain sequence equivalent to:

- `SET state-key payload`
- `SADD symbols-key symbol`
- wrapped only in `redis::pipe().atomic()`

is not acceptable when a wrong-type error in the later command can leave the earlier write committed.

## Preferred implementation

Prefer one Lua script that:

1. receives the state key, symbols key, canonical symbol, and already serialized JSON payload;
2. checks Redis key types before mutation;
3. allows only:
   - state key: `none` or `string`;
   - symbols key: `none` or `set`;
4. returns a deterministic error before either mutation when either key has an incompatible type;
5. performs `SET` and `SADD` only after both validations succeed;
6. executes as one Redis script invocation.

An equivalent mechanism is allowed only when its tests prove the same both-or-neither semantics under deterministic command-level failure.

Do not add a dependency if the existing `redis` crate already provides the required script support.

Serialize before issuing any Redis mutation.

## Required tests

Tests must prove all of the following using a real isolated Redis instance where integration coverage is required:

1. Successful write creates the serialized payload.
2. Successful write creates symbol membership.
3. `get_market_state` reads the new value.
4. `list_symbols` finds the symbol.
5. Repeated write replaces the payload.
6. Repeated write retains exactly one set membership.
7. An unrelated Redis key survives.
8. Wrong type for the symbols index:
   - returns the expected cache error;
   - preserves the pre-existing invalid index value;
   - creates no new state payload.
9. Wrong type for the state key:
   - returns the expected cache error;
   - preserves the pre-existing invalid state value;
   - creates no symbol membership.
10. Serialization failure performs no Redis write when deterministic failure can be exercised through the existing API boundary.
11. Existing preserve/validate, corrupt-data, repeated-write, and targeted-reset tests continue to pass.

Failure tests must inspect Redis contents after the error. Verifying only the returned error is insufficient.
