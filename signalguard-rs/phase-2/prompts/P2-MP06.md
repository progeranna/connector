## Goal

Remove the Live dashboard Redis N+1 pattern.

The dashboard currently obtains the sorted registered-symbol list and then awaits one `get_market_state` Redis call per symbol. Replace that loop with one explicit bulk cache operation while preserving exact symbol-to-state identity and all existing public dashboard behavior.

## Required implementation

### Redis cache API

Add a narrowly scoped bulk market-state read API to `RedisCache`.

The API must:

1. accept an ordered slice/list of canonical `Symbol` values;
2. preserve the input symbol order in its result;
3. keep every requested symbol explicitly associated with its own result;
4. represent a missing Redis value as `None` for that exact symbol;
5. use one Redis `MGET` command or one single executed bulk pipeline for all requested state keys;
6. perform no awaited per-symbol Redis `GET` loop;
7. return immediately for empty input without requiring a Redis round trip;
8. preserve the existing in-memory/test cache behavior;
9. deserialize every non-missing payload using the existing cache error boundary;
10. reject malformed JSON as `CacheError::InvalidData` or the existing equivalent cache-data error;
11. reject an embedded payload symbol that does not equal the symbol associated with the requested key;
12. never shift later payloads onto earlier symbols when a value is missing or invalid.

A preferred result shape is an ordered collection of explicit `(Symbol, Option<MarketState>)` entries or an equivalently unambiguous typed structure. Do not expose a raw unlabelled `Vec<Option<MarketState>>` to dashboard business logic.

Do not modify the P2-MP05 Lua write script or atomic-write semantics except for unavoidable formatting caused by touching the same file.

### Dashboard handler

Update the Live dashboard summary path in `src/api/handlers.rs` so that:

1. `list_symbols()` remains the source of the sorted registered-symbol order;
2. all corresponding market states are loaded by exactly one call to the new bulk cache API;
3. no Redis await occurs inside the per-symbol summary-building loop;
4. every `DashboardSymbolSummary.symbol` remains paired with the correct state and health evaluation;
5. missing state still produces `state: null` and `health: null` for that symbol;
6. recent-anomaly filtering and health scoring remain symbol-local;
7. response ordering remains unchanged;
8. Demo behavior remains unchanged;
9. `/dashboard/summary`, `/symbols`, `/market/{symbol}/state`, `/market/{symbol}/health`, timeline, anomalies, and runtime routes remain unchanged;
10. cache errors continue to increment the cache-error counter and map through the existing `ApiError` boundary.

Prefer separating the async bulk-load boundary from a pure summary-mapping helper when that improves testability, but do not begin broader read-service or DTO architecture work.
