## Implementation summary

Query-key construction is centralized in `web/src/features/dashboard/queryKeys.ts` without changing endpoint behavior. The module exposes the established roots and factory names:

- dashboard summary: `dashboardSummaryQueryKey` and `dashboardSummaryQueryKeyForMode(mode)`;
- market timeline: `marketTimelineQueryKeyRoot`, `marketTimelineQueryKeyRootForMode(mode)`, and `marketTimelineQueryKey(symbol, mode)`;
- runtime mode/status: `runtimeModeQueryKey`.

The timeline factory delegates symbol identity to the existing `parseSymbolId` boundary, preserving canonical uppercase/trimmed `SymbolId` values and the existing `null` disabled-query identity for absent or invalid input. `api.ts` continues exporting the same names, so existing consumers and `api.test.ts` remain compatible. Hooks use the centralized factories, while fetch functions, `AbortSignal` propagation, enabled state, and refresh policy remain byte-for-byte behaviorally unchanged.
