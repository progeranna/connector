## Implementation summary

`RedisCache::set_market_state` now serializes `MarketState` before obtaining a Redis connection or invoking any mutation. It then executes one `redis::Script` Lua invocation with two keys and two arguments:

- `KEYS[1]`: `signalguard:market_state:<SYMBOL>`;
- `KEYS[2]`: `signalguard:symbols`;
- `ARGV[1]`: canonical symbol;
- `ARGV[2]`: serialized market-state payload.

The script performs all deterministic command-compatibility checks before mutation:

1. the state key must be absent or a Redis string;
2. the symbol-index key must be absent or a Redis set;
3. otherwise the script returns a deterministic Redis error before either write;
4. only after both checks pass does it execute `SET` followed by `SADD` inside the same Lua invocation.

This is not a plain `MULTI`/`EXEC` or `redis::pipe().atomic()` sequence. The wrong-type failure modes that could otherwise permit a partial write are prevalidated before the mutation section. Script failures remain inside the existing `CacheError::Redis { operation: "set_market_state", ... }` boundary, preserving operation context.
