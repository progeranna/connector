## Goal

Make Redis latest-market-state registration atomic so the market-state payload and symbol membership are updated both-or-neither.

Current logical records:

- state payload: `signalguard:market_state:<SYMBOL>`
- symbol index: `signalguard:symbols`

The implementation must prevent partial mutation under deterministic Redis wrong-type failures.

A plain `MULTI`/`EXEC`, `redis::pipe().atomic()`, or sequential `SET` then `SADD` is insufficient because a later command-level failure can leave an earlier write committed.

## Required implementation semantics

Use one Redis Lua script or an equivalent mechanism with demonstrably identical semantics.

The preferred script must:

1. receive the state key and symbol-index key through `KEYS`;
2. receive canonical symbol and serialized payload through `ARGV`;
3. validate the state key type before mutation:
   - allowed: `none`, `string`;
4. validate the symbol-index key type before mutation:
   - allowed: `none`, `set`;
5. return a deterministic Redis error before any mutation when either type is incompatible;
6. perform `SET` and `SADD` only after both validations succeed;
7. execute both writes within the same script invocation;
8. preserve operation context through the existing `CacheError::Redis` mapping.

Serialization must complete before any Redis mutation is attempted.

## Compatibility requirements

Preserve all of the following:

- `RedisCache::set_market_state` public signature;
- `RedisCache::get_market_state` behavior;
- `RedisCache::list_symbols` behavior;
- `CacheError` public variants;
- JSON payload format;
- key namespace and exact key names;
- replacement semantics for an existing valid string payload;
- idempotent symbol registration through set membership;
- startup preserve/reset policy;
- validation behavior;
