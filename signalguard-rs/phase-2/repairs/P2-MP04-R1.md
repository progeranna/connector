## Independent review findings

The candidate is not acceptable yet for reasons beyond the lint failure.

### 1. Frontend lint failure

`web/src/features/dashboard/api-contract.test.ts` contains explicit `any` types and fails `@typescript-eslint/no-explicit-any` in exact-head CI.

The repair must use `unknown` plus narrow structural types/type guards or another lint-clean approach. Do not disable or suppress the lint rule.

### 2. Mutation tests do not test compatibility failure

The current test mutates the contract and merely asserts that the mutated value changed. That cannot prove that incompatible contract drift is rejected.

Create one reusable compatibility assertion/validator that:

- accepts the real checked artifact;
- throws or returns an explicit failure for an incompatible artifact;
- is exercised against the real artifact as PASS;
- is exercised against isolated cloned fixtures where each of the following changes and must FAIL:
  - a parameter name;
  - requiredness or nullability;
  - an enum value/set;
  - a required response property.

The fixture tests must fail because the compatibility validator rejects the fixture, not because the test directly checks the mutated field.

### 3. Contract schema source is manually duplicated and not sufficiently typed

The current schema components are assembled as free-form `serde_json::Value` objects independent of the actual DTO/query Rust types. A DTO field/type change can compile while the contract remains stale.

Repair the architecture so component schemas are mechanically anchored to the backend DTO/query types. Acceptable approaches include a focused schema derive library or narrowly scoped typed schema definitions/traits associated with the actual Rust types. The final source must provide compile-time or executable drift coupling to the DTO/query types rather than a second manually maintained field inventory.

Do not add handler annotations and do not modify runtime behavior.

A small focused dependency is allowed if justified. Any `Cargo.toml`/`Cargo.lock` change must be minimal and directly related to schema generation.

### 4. OpenAPI 3.0 nullable references are invalidly represented

For OpenAPI 3.0.3, a Reference Object must not rely on sibling `nullable` fields. The current form:

```json
{"$ref":"#/components/schemas/...","nullable":true}
```

must be replaced with an OpenAPI-3.0-valid representation, such as an `allOf` wrapper with `nullable: true`, or the artifact may move to OpenAPI 3.1 with correct union/null semantics if the entire document and tests are updated consistently.

Add an executable test for nullable referenced dashboard `state` and `health`.

### 5. Optional request fields must reflect accepted null semantics

Inspect actual Serde behavior for `RuntimeModeSwitchRequest` optional fields. Fields represented by `Option<T>` accept absence and JSON `null` unless custom deserialization says otherwise. The contract must distinguish:

- not required;
- nullable when explicitly supplied as `null`.

Add tests for representative request fields such as `symbols`, `reset_state`, and `reset_storage`.

### 6. Error responses are missing

The current operations publish only `200` responses. Inventory the actual shared API error body and reachable status codes from existing handlers/`ApiError` without changing behavior.

Add the existing error response schema and the accurate error status responses needed for the declared web-console endpoints. Do not invent new errors or change status codes.

### 7. Backend route/method inventory proof is incomplete

The current backend contract test checks path count and one parameter only. Add executable proof covering:

- every declared JSON route path;
- every declared HTTP method, including both GET and POST on `/runtime/mode`;
- actual path parameter name `symbol`;
- actual query parameter names for dashboard, timeline, and anomalies;
- explicit exclusion/disposition of `/metrics` as Prometheus text.

Shared path constants are useful but are not by themselves sufficient proof that methods cannot drift. Use route probes, a typed method/path inventory shared with tests, or equivalent executable validation.

### 8. Missing required backend drift tests

Add executable tests proving:

- the checked artifact bytes equal generated bytes;
- an isolated intentionally stale artifact/check fixture returns failure/non-zero behavior;
- deterministic generation remains stable;
- schema representation covers decimal strings, UUID, date-time, enums, arrays, nested objects, required-nullable fields, and request optional/null semantics.

Do not rely only on the CI shell command as the test implementation.
