## Required repairs

### 1. Preserve route and popup anomaly formatting separately

The pre-MP03 route and popup intentionally used different display formatting for anomaly values.

The shared view model must preserve both without returning raw DTO values to presentation.

Use an explicit readonly display-variant shape or an equivalently clear model, for example:

```ts
type MarketDisplayVariants = Readonly<{
  route: string;
  popup: string;
}>;
```

At minimum, `observed` and `threshold` must carry both route and popup representations.

Preserve exact existing behavior:

- route representation: generic numeric formatting with `en-US` and at most four fraction digits, no anomaly-type unit suffix;
- popup representation: the existing type-aware formatting, including percentages, durations, `/m`, `gap`, and `limit` suffixes;
- null/NaN values: `—` in both representations.

For example, for a `spread_spike` value of `2.5`:

- route: `2.5`
- popup: `2.500%`

`SymbolDetailPage` must use route variants.

The Dashboard symbol-detail popup must use popup variants.

Do not change formatting in generic anomaly cards, timeline components, or unrelated dashboard sections.

### 2. Preserve partial-state success behavior

The view model must explicitly preserve whether `resource.summary.state` exists.

Add a readonly boolean or discriminant such as:

`stateAvailable`

- `stateAvailable` is false;
- every state-derived metric is unavailable;
- `depthGaps` is `—`, not `0`;
- no optional state value is fabricated;
- `SymbolDetailPage` keeps the pre-MP03 `Latest normalized state` empty-state shell rather than rendering a metric list.

When state exists and `depth_sequence_gap_count` is legitimately zero, render `0`.

Do not alter the outer resource status rules from P2-MP02.
