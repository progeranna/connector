## 5. Audit purpose

Refresh the original MP00C inventory against the integrated Wave 1 + MP04 tree and produce the authoritative evidence base for P3.5-MP05.

The audit must determine, with current-tree evidence:

- unused local declarations and parameters;
- unused exported runtime symbols and type exports;
- files with no production or test importers;
- unused `dependencies` and `devDependencies`;
- import cycles;
- unreachable branches;

- which original MP00C findings disappeared, changed, or remain after MP01–MP04.

This task audits only. It does not authorize cleanup implementation.

## 6. Required classification

Classify every candidate as exactly one of:

- `CONFIRMED` — direct repository/compiler/importer evidence proves it is removable;
- `PROBABLE` — strong evidence, but one explicit uncertainty remains;
- `NEEDS_LOCAL_VERIFICATION` — evidence is incomplete or tool output conflicts;
- `FALSE_POSITIVE` — the candidate is used or required;
- `INTENTIONAL` — apparently unused but deliberately retained for a documented contract.

Only `CONFIRMED` candidates may be proposed for MP05 writable scope.

Do not promote a result to `CONFIRMED` based on one static-analysis tool alone.

## 7. Required analysis

### 7.1 Compiler unused checks

Run one-shot TypeScript checks enabling unused-local and unused-parameter diagnostics without modifying tracked configuration.

Record:

- exact commands;
- exit codes;
- every diagnostic with file and symbol;
- whether the result is production, test, script, configuration, declaration, or generated code;
- false-positive analysis.

Do not silently ignore diagnostics from test or build tooling.

### 7.2 Export inventory

Inventory exported symbols across the frontend and relevant root tooling.

For every candidate export:

- declaration path and symbol;
- runtime or type-only;
- all static importers;
- dynamic/import-string references;
- test-only usage;
- re-export/barrel usage;
- public-entry or generated-contract status;
- classification and evidence.

Account for TypeScript path aliases, lazy/dynamic imports, Vite entrypoints, scripts, tests, and generated files.

### 7.3 No-importer files

Identify files with no direct importer and classify entrypoints, route modules, scripts, test setup, generated files, declarations, and tooling configuration correctly.

For every genuine candidate:

- path;
- file role;
- search method;
- static and dynamic importer evidence;
- classification.

### 7.4 Dependency audit

Audit every direct `dependency` and `devDependency` in `web/package.json` and any relevant root manifests.

For each apparently unused package:

- manifest location and version;
- source imports/requires;
- configuration/plugin references;
- script usage;
- transitive-only or type-only considerations;
- build/test/runtime role;
- classification.

No package or lockfile change is permitted.

### 7.5 Cycle analysis

Analyze frontend import cycles and any relevant TypeScript tooling graph.

Record:

- exact tool and version;
- exact command;
- each cycle path;
- whether it is runtime, type-only, test-only, or false positive;
- whether it creates a valid MP05 cleanup candidate.

A cycle alone is not proof of dead code.

### 7.6 Reachability and compatibility branches

Inspect suspicious unreachable or compatibility-only branches from the original MP00C-WEB inventory and newly discovered candidates.

For each:

- exact location;
- current callers or triggering conditions;
- tests/contracts protecting it;
- classification;
- deletion risk.

### 7.7 Original-audit delta

Provide a finding-by-finding delta against the original MP00C-WEB report:

- still present and unchanged;
- still present but evidence/classification changed;
- removed by MP01–MP04;
- newly introduced;
- original false positive confirmed;
- unresolved.
