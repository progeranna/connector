## 6. Canonical behavior to preserve

The new module must own:

- the `HealthScore` component
- score/status tone resolution
- score text class
- score bar class
- minimum progress-bar width
- compact layout
- regular layout

Keep helper functions private unless a concrete focused-test requirement makes a public export necessary. Prefer testing the rendered component contract rather than exporting implementation helpers.

### 6.1 Ordered score/status precedence

Preserve the current ordered logic exactly:

1. healthy status OR score at least 80 -> healthy tone
2. otherwise degraded status OR score at least 50 -> degraded tone
3. otherwise unhealthy status OR score below 50 -> unhealthy tone
4. otherwise neutral tone

This ordering is intentional. It means, among other accepted cases:

- degraded status plus score 95 keeps degraded wording/badge semantics but uses the healthy score color
- unhealthy status plus score 95 uses the healthy score color
- healthy status plus a low numeric score can retain the healthy score color

Do not replace this with generic `toStatusTone(status)` or another status-only mapping.

Status wording and the surrounding status badge remain owned by the callers and remain independently status-derived.

### 6.2 Null and numeric-zero behavior

Preserve:

- null score -> displayed `—`
- null score -> neutral text and neutral bar
- null score -> 0% width
- numeric zero -> displayed `0`
- numeric zero -> unhealthy score tone
- numeric zero -> minimum 4% visible bar
- any non-null score below 4 -> minimum 4% bar

Do not conflate null with zero.

### 6.3 Visual variants

Preserve the exact existing class tokens and DOM structure for:

- compact desktop-preview score layout
- regular mobile-card score layout
- text colors
- bar colors
- wrapper widths/flex behavior
- bar height/radius/background

The desktop caller must continue to use the compact variant. The mobile caller must continue to use the regular variant.

There must be no visual redesign, class normalization, copy change, or responsive change.

### 6.4 Caller contracts

Preserve:

- desktop table columns, widths, row structure, keys, callbacks, click behavior, Enter/Space activation, `preventDefault`, role, tabIndex, aria labels, and focus classes
- mobile native-button structure, callbacks, keys, aria labels, focus classes, and mobile-only presentation
- input order and immutability
- no sorting, limiting, deduplication, mutation, Demo fallback, query ownership, or resource ownership inside presentation callers
