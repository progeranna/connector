## 7. Required policy model

Refine bundle reporting to distinguish three raw-byte metrics:

1. **Initial JS** — the complete static JavaScript closure required by all Vite entry chunks.
2. **Largest JS** — the largest emitted JavaScript asset.
3. **Total JS** — every emitted `.js`, `.mjs`, or `.cjs` asset under `dist/assets`, including async and otherwise unreferenced assets.

The initial closure must be derived reproducibly from the Vite manifest:

- enable production manifest output in `web/vite.config.ts`;
- read `dist/.vite/manifest.json`;
- start from every manifest record with `isEntry: true` and a JavaScript `file`;
- recursively include only static `imports` edges;
- do not include `dynamicImports` in initial JS unless the same asset is also statically reachable;
- deduplicate assets by normalized emitted path;
- fail clearly on a missing, malformed, inconsistent, or cyclicly invalid manifest rather than silently guessing.

Total JS must remain filesystem-based so that unreferenced or unexpectedly emitted JavaScript cannot escape the total-size gate.

All asset paths and diagnostics must be normalized and emitted in deterministic lexical order.
