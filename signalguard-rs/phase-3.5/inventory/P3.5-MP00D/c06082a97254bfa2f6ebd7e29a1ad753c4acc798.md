## Non-negotiable preservation decision

This audit does **not** authorize weakening any guard for:

- `(uiMode, symbol)` resource identity;
- cross-symbol or cross-mode contamination;
- Live-to-Demo fallback;
- route/popup behavior and presentation differences;
- row/card identity;
- input order, input immutability, and absence of sorting/limiting inside presentation components;
- forbidden query/network/router/popup ownership;
- ticker ownership and unchanged ticker behavior;
- keyboard accessibility and click callbacks;
- loading, error, empty, unavailable, and success states.

Source-level guards remain appropriate where an illicit dependency or ownership transfer cannot be exercised reliably through DOM tests. The audit targets only overbroad scope, exact formatting, exact helper location, exact import count, stale internal names, and assertions already proven by stronger behavior/type tests.

## Historical evidence

1. **PR #41 / PR #46 — global `Date.now` false attribution.** PR #41's test expected zero global `Date.now` calls during render. React/Testing Library made two calls. PR #46 retained the real contract by proving stable output under changing clock values and keeping a direct source-level ban on `Date.now()` and zero-argument `new Date()` in the component.
2. **PR #48 / PR #49 — stale ownership guard blocked valid wiring.** PR #48 was closed because `TimelinePanel.test.tsx` still prohibited `DashboardPage` from importing/rendering `TimelinePanel`, even though compositor wiring was the legitimate next phase. PR #49 added a test-only compatibility repair that inverted the old negative assertion into an exact import-path and JSX-name requirement. The purpose changed correctly; the replacement mechanism remained overly exact.
3. **PR #51 — stale import count.** `RecentAnomaliesMobileCards.test.tsx` required exactly one production import. Accepted helper reuse made that count stale. A test-only repair replaced the count with an exact internal-module allowlist.
4. **PR #52 — helper-location churn.** Reusable presentation helpers moved from React component files into pure presentation modules to restore Fast Refresh-compatible boundaries. Tests requiring exact helper locations needed compatibility changes although behavior and ownership remained valid.
5. **PR #54 — intentional route/popup formatting difference.** Route anomaly count must remain locale-formatted (`1,000`), while popup uses the compact metric (`1K`). This is presentation-contract evidence, not incidental implementation detail.
6. **PR #56 — intentional exact visual parity.** The route mobile anomaly timestamp class was explicitly restored to `mt-1 text-xs uppercase tracking-[0.14em] text-slate-500`, while the popup metric label retained its separate font weight. These exact classes are accepted visual contracts and must remain exact.

PRs #50, #51, and #52 together show that helper deduplication and bundle recovery repeatedly changed import topology without changing the externally observable contract. PR #56 shows the opposite case: some exact presentation assertions are necessary because a one-token typography change was a real regression.

## Import and ownership conclusions

- **Exact import count is never a durable architecture contract** in the audited presentation components. PR #51 is direct evidence.
- **Exact helper location is not durable** when a helper remains within an approved pure-presentation boundary. PR #52 is direct evidence.
- **Module-category allowlists and explicit forbidden-module lists are appropriate.** They should parse import specifiers and avoid generic path fragments.

## Final audit conclusion

The suite's strongest guards are not the most brittle ones. The strongest guards combine frozen-input or state-transition behavior with narrow source-level ownership prohibitions. The brittle guards are exact import topology, function ordering, helper location, internal component names, exact call counts, and unqualified vocabulary scans. MP06A and MP06B should replace only those mechanisms while preserving resource identity, mode/symbol isolation, no fallback, presentation order/immutability, ticker ownership, route/popup parity, accessibility, callbacks, and the complete state matrix.

This report is an audit and lease recommendation only. It does not authorize implementation or update Phase 3.5 control status.
