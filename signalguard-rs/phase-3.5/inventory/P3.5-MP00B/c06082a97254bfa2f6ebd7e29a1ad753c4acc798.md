## Priority A — clear consolidation candidates

### DUP-001 — Health-score presentation in market-health desktop and mobile

**Evidence**

- `progeranna/signalguard-rs@c06082a97254bfa2f6ebd7e29a1ad753c4acc798:web/src/features/dashboard/MarketHealthDesktopTable.tsx#L130-L229`
  - `HealthScore`, `healthScoreTone`, `healthScoreTextClass`, and `healthScoreBarClass`.
  - Minimum width calculation: `score === null ? 0 : Math.max(score, 4)`.
  - Compact layout uses a flex-growing bar; regular layout uses `w-24`.
- Corresponding duplicate:
  - `...:web/src/features/dashboard/MarketHealthMobileCards.tsx#L142-L228`.
- Binding tests:
  - `...:web/src/features/dashboard/MarketHealthDesktopTable.test.tsx#L275-L320`.
  - `...:web/src/features/dashboard/MarketHealthMobileCards.test.tsx#L253-L352`.

**Semantic comparison**

The two components are exact copies modulo formatting. The ordered tone logic is identical:

1. healthy status or score at least 80 -> healthy;
2. degraded status or score at least 50 -> degraded;
3. unhealthy status or score below 50 -> unhealthy;
4. otherwise neutral.

Because conditions are evaluated from healthy to unhealthy, a high score can override degraded or unhealthy score color. Conversely, explicit healthy status can retain a healthy score color for a low score. Status wording and badge tone are derived separately from the health status, so `degraded + 95` displays degraded wording while the score is emerald. Tests explicitly bind that split.

**Intentional differences to preserve**

- Desktop preview passes `compact`; mobile uses regular layout.
- Compact and regular wrapper/bar classes must remain explicit variants.
- Score color precedence must not be replaced with plain `toStatusTone(status)`.
- Null score stays `—` with 0% width; numeric zero stays `0` with 4% minimum width.

**Canonical owner**

Create a focused owner under `web/src/features/dashboard/`, recommended path `HealthScore.tsx`, containing the component and private tone/class helpers. Do not place score precedence in `shared/lib/status.ts`; that library owns generic status parsing, not the accepted score/status override contract.

**Safe callers**

- `MarketHealthDesktopTable.tsx`
- `MarketHealthMobileCards.tsx`

**High-conflict caller deferred**

- `DashboardPage.tsx` (DUP-002), because it owns modal/resource orchestration and is reserved for later exclusive work.

**Recommended action**: consolidate now.

**Conflict risk**: medium. Production paths are leaf presentation modules, but their tests contain exact source/class assertions.

**Expected reduction**: medium. Source estimate: roughly 90–110 duplicated production lines across the two leaf modules; this is not an emitted-byte measurement.

**Recommended mini-phase**: P3.5-MP01.

**Proposed writable path lease**

- new `web/src/features/dashboard/HealthScore.tsx`
- new focused `web/src/features/dashboard/HealthScore.test.tsx`
- `web/src/features/dashboard/MarketHealthDesktopTable.tsx`
- `web/src/features/dashboard/MarketHealthDesktopTable.test.tsx`
- `web/src/features/dashboard/MarketHealthMobileCards.tsx`
- `web/src/features/dashboard/MarketHealthMobileCards.test.tsx`

## Rejected findings

### REJ-001 — Directly replace market presentation wrappers with `shared/lib/format.ts`

Rejected. `shared/lib/format.ts#L3-L40` returns `n/a` for missing compact, percent, and age values. Market-health presentation deliberately returns `—` or `Unavailable`. The canonical owner should remain `marketHealthPresentation.ts`, which may call shared formatters only after its explicit missing-value checks.

### REJ-002 — Replace custom anomaly severity pills with `StatusBadge`

Rejected. `StatusBadge.tsx#L10-L21` includes a colored dot, `w-fit`, `shrink-0`, different padding, font weight, and tracking. Preview/modal/popup anomaly pills are dotless and have compact/full variants. Shared color semantics do not prove interchangeable DOM or visual semantics.

### REJ-003 — Merge route and popup anomaly value formatting

Rejected as a single output. `marketAdapters.ts#L63-L90` and `marketAdapters.test.ts#L102-L145` prove route values are generic up-to-four-decimal numbers while popup values are type-aware percentages, durations, rates, and gap/limit labels. The view model correctly stores both variants.

### REJ-004 — Normalize `Detected` and `Detected at`

Rejected. `SymbolDetailAnomalies.tsx#L99-L172` and its tests bind popup `Detected` with time-only formatting versus route `Detected at` with route timestamp formatting. Dashboard modal/preview labels also differ by surface. No copy change is authorized.

### REJ-005 — Make route anomaly rows/cards navigate like popup cards

Rejected. `SymbolDetailAnomalies.tsx#L195-L275` uses a native button only for popup mobile; route uses an article. Tests explicitly require no route links/buttons and require popup native-button interaction. This is an intentional route/popup behavior difference.

### REJ-006 — Unify preview, full modal, route, and popup anomaly columns/counts

Rejected. Preview is limited and omits context; Dashboard full modal consumes raw full collections; route and popup have selected-symbol column sets; route anomaly count is full locale format while popup count is compact. These are semantic surface contracts, not accidental JSX duplication.

### REJ-007 — Collapse route and popup symbol-detail headers/metrics into one visual layout

Rejected. Existing shared owners already expose explicit variants/surfaces:

- `SymbolDetailHeader.tsx#L14-L63` preserves route hierarchy/copy versus compact popup header.
- `SymbolDetailMetrics.tsx#L24-L159` preserves route strip, route state panels, and popup card grid.

The current variant boundaries are the correct consolidation, not evidence for further visual normalization.

### REJ-008 — Treat loading/error wrappers as duplicate production owners

Rejected. `ErrorPanel` and `LoadingSkeleton` are already shared components. Remaining differences are state precedence, surrounding copy, height, aria-live behavior, modal identity, and route/popup ownership. Extracting another wrapper would hide state machines rather than remove duplicate logic.
