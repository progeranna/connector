## Decision and recommendation

All four route-splitting prototypes are classified `INITIAL_ONLY_BENEFIT`. None qualifies as `IMPLEMENTATION_CANDIDATE` because the contract requires total raw JS not to exceed `757217` bytes. No route boundary should be implemented by MP07 under the current policy, and neither bundle budget should be raised.

If a future implementation contract explicitly reopens an initial-only tradeoff, the measured best symbol boundary is R2b: keep `CanonicalSymbolRoute` eager and lazy-load only `SymbolDetailPage`. The exact future writable paths would be:

```text
web/src/app/CanonicalSymbolRoute.tsx
web/src/app/router.tsx
web/src/app/router.test.tsx
```

No new dependency, package, lockfile, Vite configuration, or budget change is proposed. The future tests must retain the route inventory and canonical redirect assertions, await and assert both loading boundaries, cover valid and invalid direct links, preserve `(uiMode, symbol)` query identity, and retain the existing `marketNavigationIsolation.test.tsx` coverage for route BTC → ETH and per-mode storage. A future implementation should be sequential—measure and validate the symbol boundary, then anomalies, then the combined graph—so each route’s byte and behavior delta remains attributable. Do not implement either boundary now.

Known UX tradeoffs are an intentional loading frame on direct navigation to the lazy route, and a full route-level fallback while a chunk is fetched. The eager root shell, header, ticker, dashboard graph, and Recharts remain available on initial entry, so route splitting cannot remove those shared costs. The symbol child boundary also delays the invalid-symbol state until `SymbolDetailPage` loads.

MP07 does not help the remaining `3553`-byte total-headroom requirement: the best combined prototype reduces initial raw by `4813` bytes but increases total raw by `1665`, leaving `2942` raw bytes of budget headroom. The result does not depend on a later MP09 policy change; MP09 could change classification policy, but it cannot turn these measurements into a total-JS reduction.
