## Duplicate compatibility exports and bridges

1. `api.ts` intentionally preserves query-key import paths while `queryKeys.ts` is the owner. PR history for the query-key extraction explicitly described compatibility re-exports. Tests currently consume both paths.
2. `selectedSymbol.ts` aliases `parseSymbolId` as `normalizeSelectedSymbol`; this alias is still used by production app/dashboard code.
3. `marketOrder.ts` re-exports `DEMO_MARKETS` from `marketCatalog.ts`; no current caller of that re-export was found, but local proof is required before removal.
4. `symbolPopupResource.ts` is a compatibility bridge over `symbolMarketResource.ts`; its hook remains production-used.
5. Popup-resource aliases (`SymbolPopupResourceData`, `PopupSymbolQueryBundle`) and the testable resolver may be test/public contracts even where the runtime hook is the only production import.
6. Several component prop types are imported only by focused tests. Those tests use the component module as a public contract and must be migrated deliberately before narrowing exports.
